Набор из 4 лабораторных работ и учебно-исследовательской работы, демонстрирующий владение полным стеком сетевых технологий — от физического уровня кодирования сигналов и анализа ARP/таблиц маршрутизации до конфигурирования RIP/DHCP и разбора реального трафика в Wireshark. Материалы подобраны так, чтобы показать компетенции, критичные для **SRE-инженера**: диагностика связности, анализ инкапсуляции PDU, понимание отказоустойчивых топологий и работа с инструментами observability.

## 🎯 Ключевые компетенции

- **Сетевые протоколы:** TCP/IP стек на уровне инкапсуляции PDU — ARP, IP, UDP, TCP, ICMP, DNS, DHCP, RIP.
- **Диагностика сетей:** `ping`, `tracert`, `nslookup`, `ipconfig`, анализ фрагментации IP, поведение TTL.
- **Анализ трафика:** Wireshark — разбор ICMP, DNS, ARP, TCP handshake (SYN/ACK/FIN с ISN), UDP-сессий.
- **Построение и конфигурация сетей:** NetEmul — топологии (звезда, шина, кольцо, полносвязная, многосегментная), настройка маршрутизаторов, коммутаторов, хабов.
- **Маршрутизация:** статическая, динамическая (RIP с метриками и реакцией на отказ узла), default gateway, отказоустойчивые схемы с несколькими маршрутизаторами.
- **Автоматизация адресации:** развёртывание DHCP (DORA: Discover → Offer → Request → Ack).
- **Физический уровень:** расчёт спектров для 5 методов кодирования (Манчестер, NRZ, NRZI, RZ, диф. Манчестер), избыточное кодирование 4B/5B, скремблирование полиномом.

## 🔍 Краткое содержание работ

### ЛР1 — Простейшие сети
Моделирование в **NetEmul**: сеть из 2 ПК → линейная из 3 ПК → полносвязная из 3 ПК. Изучено формирование ARP-таблиц через ARP Request/Response, построение таблиц маршрутизации (Destination, Mask, Gateway, Interface, Metric), инкапсуляция UDP в Ethernet/IP-кадры. Настроен manual routing через промежуточный узел с включением IP-forwarding.

### ЛР2 — Локальные сети
Сравнение трёх архитектур:
- **Концентратор (hub)** — широковещательная рассылка на все порты, все узлы видят чужой трафик.
- **Коммутатор (switch)** — адресная пересылка на основе MAC-таблицы коммутации с TTL записей (300 сек).
- **Многосегментная сеть** — 3 подсети, 10 узлов, выбор топологии «последовательная» по критериям надёжности/производительности/стоимости (кольцо и общая шина отклонены).

### ЛР3 — Маршрутизация и сетевые сервисы
Построение сетей с 1, 2 и 3 маршрутизаторами в отказоустойчивых топологиях (выбрана топология с полным соединением маршрутизаторов — выход из строя одного линка не ломает сеть). Настроены:
- **Статическая маршрутизация** и default gateway (0.0.0.0).
- **Динамическая маршрутизация по RIP** — наблюдение за RIP-запросами каждые 30 сек, реакцией на отказ узла (инкремент метрики, ускорение запросов до 5 сек).
- **DHCP-серверы** на каждом маршрутизаторе с автоматическим получением настроек клиентами (DORA).
- Детально разобран **TCP three-way handshake** (SYN → SYN-ACK → ACK) с ISN (Initial Sequence Number) и механизм закрытия соединения (FIN → ACK).

### ЛР4 — Анализ трафика в Wireshark
Реальный трафик с хоста студента (целевой сайт — visitkrakow.com):
- **`ping`**: обнаружена фрагментация IP при payload > 1472 байт (MTU = 1514), изучены флаги MF (More Fragments), построена зависимость количества фрагментов от размера пакета.
- **`tracert`**: механизм инкремента TTL, различия ICMP Echo Reply (type 0) и Time Exceeded (type 11), эффект ключа `-d` (отключение reverse DNS).
- **DNS**: рекурсивные/итеративные запросы, типы записей (A, AAAA, NS), структура DNS-пакета (Header 12 байт, Questions, Answers, Authority, Additional), работа CDN и вынос статики на поддомены.
- **`nslookup`**: получение авторитативных ответов от Name Server, разбор полей ресурсных записей (NAME, TYPE, CLASS, TTL, RDLENGTH, RDATA).

### ДЗ/УИР — Методы кодирования
Для собственного сообщения (`КрКК` = `CAF0CACA`, 32 бита) рассчитаны спектры сигналов для 5 методов физического кодирования при пропускной способности канала **C = 10 Мбит/с**. Применены:
- **Логическое кодирование 4B/5B** (избыточность 25%, устранение длинных последовательностей нулей).
- **Скремблирование** полиномом `Bi = Ai ⊕ Bi−3 ⊕ Bi−5`.

По результатам сравнительного анализа лучшим методом для передачи выбран **NRZI + 4B/5B**:
- Наименьший спектр `S = C/4 = 2.5 МГц` (в 2 раза уже, чем у Manchester).
- Наименьшая требуемая полоса пропускания `F = 33 МГц`.
- Отсутствие постоянной составляющей.
- Возможность обнаружения ошибок по запрещённым символам.
- Низкая стоимость реализации (2 уровня потенциала).

## 💡 Применимость в SRE-практиках

| Навык из курса | Применение в SRE |
|----------------|------------------|
| Анализ ARP, таблиц маршрутизации, TTL | Диагностика проблем связности, выявление петель маршрутизации, troubleshooting L2/L3 |
| Работа с Wireshark | Разбор инцидентов, анализ latency, обнаружение аномального трафика, расследование сетевых сбоев |
| Понимание TCP handshake, ISN, фрагментации, MTU | Диагностика проблем с соединениями, настройка MSS/MTU, анализ retransmission'ов |
| Настройка DHCP, DNS, RIP | Понимание работы критичных инфраструктурных сервисов, их отказоустойчивости и деградации |
| Моделирование отказоустойчивых топологий | Проектирование redundant-архитектур, понимание single point of failure |
| Расчёт спектров и кодирование (L1) | Базис для понимания физических ограничений каналов (полезно при работе с DCI, WAN, capacity planning) |
| Анализ ICMP type 0 vs type 11 | Понимание работы `tracert`, диагностика TTL-related проблем и маршрутизации |
